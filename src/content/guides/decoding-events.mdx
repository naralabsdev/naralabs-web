# Decoding Events

NaraLabs uses **SEP-0048** event schemas to turn raw Soroban event payloads into readable fields and summaries.

## Decode pipeline

1. **Index** — Atlas worker ingests events from Stellar RPC (level 1–2)
2. **Match schema** — Registry lookup by contract + event type
3. **Decode** — Map topics and value to semantic fields (level 3)
4. **Preview** — Generate `summary_preview` for list views

## Decode status

| Status | Meaning |
| --- | --- |
| `decoded` | Schema matched; semantic fields available |
| `raw` | Indexed but no schema or partial decode |

## Schema registry

Most Soroban contracts emit events **without on-chain metadata**. Contract authors publish a **`naralabs.schema.yaml`** that maps:

- `prefix_topics` — topic symbols emitted on-chain
- `params` — human-readable field names, types, and locations

This is **developer-authored** for legacy/manual contracts. The CLI writes a starter template when WASM has no event spec; you edit it before `registry publish`.

## Decode API

For raw RPC payloads (before indexing), use the [Decode API](/docs/api/decode-api):

```bash
curl -X POST "http://localhost:8080/v1/decode" \
  -H "Authorization: Bearer $NARALABS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "network": "testnet", "contractId": "...", "topicsJson": [], "valueJson": {} }'
```

## Raw vs decoded in the UI

- **Homepage & list tables** show decode badges and summaries
- **Event detail** shows full JSON topics/value plus decode metadata
- **Filters** on `/events` let you narrow to decoded or raw-only events

## Contributing schemas

```bash
naralabs init my-schema
# edit my-schema/naralabs.schema.yaml
cd my-schema
naralabs registry validate
naralabs registry publish
```

Full API format: [Atlas README](https://github.com/naralabsdev/naralabs-atlas#schema-registry-sep-0048) or `http://localhost:8080/docs`.
